# KV cache 机制探索：收益、反例与因果性边界

日期：2026-09-20。本地实验分支 `feat/kv-cache-quantization`，本轮只扩展 CPU lab，不增加服务端格式或硬件支持。基础审计见 [原项目审计](kv_cache_audit_zh.md)，已有格式及自适应机制见 [量化探索说明](kv_cache_quantization_exploration_zh.md)。

本轮真正要回答的是：**额外保存哪一小部分信息，能比直接提高位宽更划算？** 不把新机制数量当成收益，也不把张量重构变准直接等同于 attention 或生成质量变好。

## 1. 已实现的四种机制

| 机制 | 实现入口 | 目标 | 主要成本 |
| --- | --- | --- | --- |
| 页内逐通道中心化 | `QuantSpec(center=True)` | 先去掉页面公共偏移，量化较小的波动部分 | 每页保存 FP32 `[1,H,D]` 均值 |
| 低秩量化残差修正 | `residual_rank=r` | 用结构化修正恢复量化丢失的相关信息 | FP32/FP16/BF16 `[H,T,r]` 和 `[H,r,D]` 因子；封页执行 SVD |
| 按实际误差稀疏修正 | `error_fraction=f` | 优先修复最大重构错误，不按原值幅度选点 | 每个修正点 FP32 残差和 INT32 索引，共 8 字节 |
| 页内 head 独立选型 | `PageQuantPolicy(headwise=True)` | 避免一个敏感 head 迫使整页所有 head 升精度 | 更多格式描述、解码分派与独立编码操作 |

实现位于 [codec](../tools/kv_cache_codec_lab.py)、[分页与策略](../tools/kv_cache_quantization_lab.py)、[实验驱动](../tools/explore_kv_quantization.py)。所有新策略默认关闭。原有 INT2～INT8、FP8、NF4、FP4、旋转、分组与 affine 继续可组合使用；native 不允许附加有损变换。

这些是机制借鉴及本地组合，不宣称论文原创：[SageAttention](https://arxiv.org/abs/2410.02367) 提供量化 attention 的相关背景；[GEAR](https://arxiv.org/abs/2403.05527) 已提出量化结合低秩和稀疏误差修正。本实现采用每页每 head 的确定性完整 SVD 参考，不是 GEAR 的完整复现或高效设备实现，也不继承其模型质量结论。

## 2. 中心化不能直接丢掉页间偏移

对一页 `X[T,H,D]`，存储 `C=mean_T(X)`，量化 `X-C`。解码恢复 `X_hat=decode(payload)+C`。均值在 FP64 累加后存 FP32；先中心化再旋转，解码先逆旋转、裁剪，再加回均值。这样原坐标系、非二次幂 D 和旁路修正的次序是明确的。

对 K，若所有历史 token 减去同一个中心，`q·C` 是整行共同常数，在 softmax 中可消去。但**每页有各自的中心，不能跨页面直接忽略**：不同页的 `q·C_page` 不同，漏掉它会改变页面之间的注意力质量。当前参考实现始终还原中心，再做逐页 attention；未来若融合到 score 中，也必须加回每页的偏移后再参与全局 online softmax。

对 V，加回中心同样不能省略：它对输出的贡献取决于该页的 attention 权重和。实现还原 V 后正常累加，不作近似简化。

## 3. 修正真正的量化残差，而不是原张量

先完成原 codec 的量化、逆旋转、中心恢复，得到 `X0`，再计算 `E=X-X0`。这样修正适配已有所有格式，也不会把变换空间的残差误加到原空间。

低秩版本逐 head 对 `[T,D]` 残差做 SVD，保存 `L=U_r S_r`、`R=Vh_r`，解码为 `X0+LR`。截断因子必须 clone 并持有紧凑独立存储，否则一个小切片可能仍持有完整 SVD 矩阵，破坏容量统计。rank 必须在 `[0,min(T,D)]` 内；非有限中间量明确失败。

第一轮发现 FP32 因子过贵后，继续增加 `residual_dtype="float16"/"bfloat16"`。低精度版本将奇异值增益平衡分配为 `L=U_r sqrt(S_r)`、`R=sqrt(S_r)Vh_r`，再分别转换到目标存储类型，避免全部增益集中在一个因子；这不能保证所有输入不溢出，超范围仍报错。解码时转为 FP32 相乘；若再启用稀疏修正，依据这两个实际存储的低精度因子重新计算剩余误差，而不是依据未压缩的 SVD 结果。

稀疏版本从当前剩余误差中选 `ceil(f·T·H·D)` 个最大绝对误差位置，以稳定排序解决并列值。若同时启用低秩，先完成低秩修正，再选择剩余错误，避免两部分反复修正同一误差。解码按“基础重构→低秩加法→稀疏加法”执行。

这与原先 `outlier_fraction` 不同：旧策略在量化前保留各组最大幅值元素，并改变主体校准范围；新策略在量化后修复最大错误，不改变基础量化。两者可组合，但不能默认组合就更好；Frobenius 误差改善也不保证 softmax 输出改善。

### 容量账必须与直接升位宽比较

设页面 T、维度 D、rank r，暂不含尾部，附加有效位宽为：

```text
FP32 中心：             +32/T bit/元素
FP32 低秩因子：         +32r(1/T + 1/D) bit/元素
FP16/BF16 低秩因子：    +16r(1/T + 1/D) bit/元素
FP32+INT32 稀疏修正：   约 +64f bit/元素（实际选点向上取整）
```

T=32、D=64 时，中心增加 1 bit，rank1 增加 1.5 bit，rank2 增加 3 bit，1/32 稀疏修正增加 2 bit。原 INT4 + G32 FP32 scale 已是 5 bit；rank2 后达到 8 bit，甚至比同 scale 的 INT6（7 bit）更大。不能只比较 INT4 修正前后的误差而隐去这些代价。

## 4. head 独立选型与共享生命周期

原页面级策略对每个候选检查最差 head；任一 head 不合格，整个页面都需换格式。新策略把每个 head 看成独立的 `[T,1,D]`，分别执行同样的预算搜索，并真正保留各自位宽的 payload，不用最高位宽把所有 head 补齐。

解码按原 head 顺序拼接，GQA 的 query-head/KV-head 映射不变。每个 head 仍有相同相对/绝对重构预算，但这不意味着最终 attention 输出误差必然下降。字节统计包含每个 head 的全部 tensor；Python 描述符、对象、分配器对齐和临时峰值仍未计入。

封页后不会重选、重标定或重新修正；fork 共享旧页，仅复制高精度尾部。对外 `page_report()` 返回各 head 的描述副本，不暴露可修改的共享 tensor。

## 5. 新发现并处理的因果性问题

**因果 mask 只能屏蔽未来 token 的显式 attention，并不能消除量化统计间接读取未来 token 的影响。** 例如用 0～31 token 的均值量化第 0 个 K，再计算 query 0，即使 mask 屏蔽了 1～31，它的 K 编码仍受这些 token 影响。channel 分组、整页残差拟合、按页选型也有同样问题。

新页面记录 `token_coupled`。默认 `attend()` 检查：参与跨 token 统计的页面，结束位置不能晚于最早 query 的位置。否则直接报错，要求将当前 query chunk 保留在高精度尾部。固定 per-token codec、无跨 token 修正时不受此限制；sink 的 native 页也无需限制。

只有显式 `allow_retrospective=True` 才允许离线回顾性重构比较；这不是生产 fallback。旧 `--adaptive` 和默认格式比较保持历史数值可复现，但输出标注 `retrospective_reconstruction`。其中跨 token 策略的结果不能作为在线因果生成验证。

本轮 `--mechanisms` **统一 R=32，最后 8 个 query 均落在高精度尾部**，所有量化页面结束于 query 之前，使用默认因果检查；输出标注 `causal_tail_protected`。因此不能与旧 R=0 表格直接比较压缩比。高精度尾部不是免费的，这里一并计入容量。

## 6. 实验范围

```bash
python -m tools.explore_kv_quantization --mechanisms --seed 2026
python -m tools.explore_kv_quantization --mechanisms --seed 2027
python -m tools.explore_kv_quantization --mechanisms --seed 2028
```

PyTorch 2.6.0+cpu，单线程，BF16 输入；T=256、Hkv=2、Hq=4、D=64、Q=8、P=32、R=32。最终 23 种配置 × 5 种分布 × 3 个种子，共 345 个小型探索案例，不是新增测试套件。[完整结果 CSV](kv_cache_mechanism_results.csv) 保存每个种子的压缩比、有效位宽、K/V 与 attention 误差。表中压缩比与相对误差分别对三个种子取算术平均。

五类分布是普通高斯、固定通道离群、常量偏移、每 32 token 不同的随机通道偏移、低秩相关信号加小噪声。后两者是为暴露机制行为构造的压力样本，不代表真实模型的分布占比。比较均在同一配置的未量化 BF16 K/V 上计算 FP32 dense attention 参考。

| 分布 | 配置 | 平均压缩比 | 平均 attention 相对 L2 | 三个种子的误差范围 |
| --- | --- | ---: | ---: | ---: |
| page_shifts | `int4_sym` | 2.510× | 6.28% | 5.88%～6.68% |
| page_shifts | `int6_sym` | 1.969× | 1.40% | 1.21%～1.60% |
| page_shifts | `int4_center` | 2.207× | 0.99% | 0.92%～1.03% |
| channel_outliers | `int4_outliers` | 1.969× | 44.78% | 29.45%～66.46% |
| channel_outliers | `int4_error_1_32` | 1.969× | 36.19% | 21.30%～49.36% |
| channel_outliers | `int6_sym` | 1.969× | 12.38% | 9.15%～17.33% |
| channel_outliers | `adaptive` | 1.419× | 1.71% | 1.31%～2.26% |
| channel_outliers | `adaptive_extended` | 1.479× | 3.37% | 2.04%～5.15% |
| channel_outliers | `adaptive_headwise` | 1.639× | 4.62% | 2.42%～5.81% |
| correlated | `int4_rank2` | 1.778× | 15.62% | 13.42%～19.60% |
| correlated | `int6_sym` | 1.969× | 6.41% | 4.97%～7.29% |

从这组证据得到的选择，而不是普遍排名：

- **中心化值得保留为分布相关选项**：页间均值漂移下，相比 INT6，它同时有更高压缩比（2.207× vs 1.969×）与更低平均误差（0.99% vs 1.40%）；但普通高斯下并不改善平均误差，也要多存中心，不能默认启用。
- **稀疏修正的选点依据有影响**：相同容量下，通道离群样本的“按误差修正”优于“按原幅值旁路”（36.19% vs 44.78%）；但直接 INT6 同样容量误差仅 12.38%。因此这不是胜过升位宽的证据。
- **当前 FP32 低秩 sidecar 不宜优先推广**：相关分布中 rank2 相比裸 INT4 改善了误差，但比 INT6 更占容量、误差仍更高。下一步必须先压低因子成本或针对真正低秩的量化残差，而不能凭原张量低秩就假定残差也低秩。
- **按 head 分配节省容量，但不是自动提升质量**：通道离群下从基础页面自适应 1.419× 到扩展候选后的 head 自适应 1.639×，平均误差也从 1.71% 增至 4.62%。仅比较相同扩展候选集，则页面级为 1.479× / 3.37%，head 级为 1.639× / 4.62%。重构预算内有多个可行解，更省字节的解不一定有更好的 attention。真实任务要额外约束 score/output 敏感性，不能只追求局部门槛下最少字节。
- **必须看多种子而非挑最好一次**：通道离群的裸 INT4 平均误差为 88.66%，范围为 58.61%～141.36%；相对 L2 可以超过 100%，不是准确率百分比。本实验仅有 3 个种子，尚不足以推断总体分布或模型表现。

最小手工检查还确认了非二次幂 D 下中心化/旋转/两级修正的组合、截断 SVD 因子的实际 storage 字节、head 选型的 append 分块一致性和 fork 隔离，以及跨 token 校准的因果拒绝路径。没有新增测试文件，没有设备吞吐或真实模型验收。

### 继续追查：因子成本减半之后怎样？

相关分布中，INT4+rank2 的 FP32 因子方案为 **1.778× / 15.62%**；FP16/BF16 因子都提高到 **2.081× / 约15.62%**，本组误差变化很小，说明减少 sidecar 精度是有效容量优化。但 INT6 为 **1.969× / 6.41%**，因此仍只是容量/误差的不同取舍，不能宣布低秩修正全面胜出。

页面偏移分布中，中心化+rank1 FP16 因子为 **2.024× / 0.90%**，较单独中心化 **2.207× / 0.99%** 略准但更占容量。实际是否值得取决于精度约束；不是任何额外修正都应保留。低精度因子还通过了实际 storage 减半和解码有限值的手工检查。

## 7. 下一步哪些机制值得做，哪些不宜直接加

| 方向 | 为什么值得研究 | 接入前必须解决的问题 |
| --- | --- | --- |
| 校准 query 子空间中的 K 误差 | K 的用途是 `QKᵀ`，不等价于重构所有方向 | 独立校准集和保留集；分布漂移；GQA；不能用评估 query 选格式再自报误差 |
| 更低位宽因子、结构化稀疏修正 | 本轮已支持 FP16/BF16 因子，INT32 单点索引仍贵 | INT8/FP8 因子尺度、误差、溢出、索引成本及融合读取；必须重新比较直接 INT6/INT8 |
| 跨页稳定通道画像 | 避免每页重复搜索所有 codec | 只用已见历史；冻结共享页面；错误画像不能静默破坏误差约束 |
| 层/head 全局容量预算 | 当前只有局部误差门槛，没有总显存约束 | 页面大小不同带来的 allocator 碎片；误差预算不可简单跨层相加 |
| 热尾部、温缓存、冷存储分层 | 用访问与敏感性分配高精度，而非全上下文同一位宽 | 旧低位宽数据不能靠反量化恢复精度；恢复需原副本或重新计算 |
| pre-RoPE K 量化 | 可能利用旋转前分布规律 | 必须正确恢复位置旋转；不能把 post-RoPE payload 简单重解释 |
| VQ/多阶段残差码本 | 更低位宽下可能优于逐标量量化 | 码本训练、版本、共享、索引与解码开销；短上下文码本成本明显 |
| token/page 稀疏读取或淘汰 | 减少读取/计算，补足仅量化节省字节的局限 | 改变 attention 语义；必须做长程检索与遗忘评估，不能只报压缩比 |

搜索曾命中 [HeadQ](https://arxiv.org/abs/2605.03562)，但核查 arXiv 原站后确认其已被作者撤回，因此不把该文的结果当作支持本方案的有效证据。query/score 空间列为待独立推导、验证的方向；全局注意力稀疏与缓存淘汰也尚未接入。

优先级应由实际 Q/K/V 和业务误差决定，而不是把所有选项默认开启。本轮已经建立可组合编码、真实字节计量、按页/head 选型和因果边界；下一阶段最缺的是独立真实轨迹、模型质量与设备性能证据，而非再增加几个格式字符串。
