# Native KV cache on SM90

This branch retains the FP8 query conversion and correct XQA workspace initialization, and removes the rejected mixed-batch split. **The final model recipe passes the frozen quality point thresholds; statistical noninferiority to BF16 remains unproved.**

Measured Python source: [`d163d5de48b201e5f767f1bf21a9437cbf1aeb42`](https://github.com/MingASA/xllm_quant_kvcache/commit/d163d5de48b201e5f767f1bf21a9437cbf1aeb42). The executed compiled xLLM source remains native C `da7c6446ff4361c8060633b04d6bfb77e6f737ff`; this candidate changes Python/Triton integration. Official base is `261274e5f45449e98d7740144c3a958a29f1fd3e`, with BF16 A `721afdabc1de1af8e594b4da3e6fa926def50821`. The CUDA/NPU build guard, byte-page geometry and lazy BF16 kernel import remain separate changes; no old research branch was merged. A subsequent documentation-only commit does not replace these measured source or binary identities. Executed binary and JIT hashes remain in the run manifests.

| Format | Resident bytes per K or V head, D=256 | Prefill and normal mixed batches | Pure decode |
|---|---:|---|---|
| BF16 (`auto`) | 512 | Official FlashInfer selection | Official FlashInfer selection |
| `fp8_e4m3` | 256 | Full packed FA3 batch, FP8 query | XQA, BF16 API query with internal FP8 conversion |
| `nvfp4` | 144 | FlashInfer native FA2 | FlashInfer FA2 tensor-core wrapper |

Native formats own byte tensors with typed aliases and no full-cache BF16 shadow. NVFP4 pages contain packed E2M1 data followed by E4M3 block-16 scales, with independent plane strides; whole-page prefix copies preserve both. On SM90, NVFP4 unpacks BF16 tiles for MMA; H800 has no Blackwell FP4 Tensor Core compute. GDN convolution/recurrent states retain official dtypes, state interface and budgets. Resident-byte accounting is independent of virtual reservation. The inherited NVFP4 path has separate historical evidence; it is not newly qualified by the FP8 results below.

Use `--kv_cache_dtype=fp8_e4m3` with the CUDA Python Executor. Quantized paths accept `--kv_cache_prefill_backend=auto|fa2|fa3` and `--kv_cache_decode_backend=auto|flashinfer|xqa`; incompatibility fails explicitly, without failure-driven fallback. The evaluated Qwen3.8-27B recipe is **FA3/XQA, `--kv_cache_k_scale=0.125 --kv_cache_v_scale=0.5`, and unit query conversion scale**. This is an explicit model recipe, not a universal default or a calibration guarantee. NVFP4 requires FA2/FlashInfer; its historical recipe uses global scales 1/1. Other positive normal FP32 scales accepted by the shared interface are not thereby numerically qualified.

The sole V=.5 candidate was frozen using an independent, untimed BF16 cohort of 136 requests, without formal quality labels. Compared with V=.0625, V clipping fell from 749,348 to zero out of 8,681,488,384 observations, and reconstruction MSE fell from `.021875646033588377` to `.0024235660469954477`. Nonzero values rounded to zero increased from 581,418 to 4,657,459. The decoded V range grows from ±28 to ±224 while its zero-rounding threshold grows eightfold. These observations establish a reconstruction tradeoff on that cohort; formal quality was evaluated separately, without further scale tuning.

XQA requires zeroed workspace on first use, including its completion counters. The backend clears the allocated decode workspace **once during construction, before capture**, with no per-token memset. Its paging contract requires initialized resident pages, stable Graph metadata addresses, valid host indptr/tail lengths and a page-aligned maximum context. Padded Graph rows safely read initialized reserved page 0 and their outputs are discarded. XQA materializes contiguous current Q when needed; it does not copy the KV history into BF16.

BF16 in the API/runtime report describes XQA's input tensor. In the pinned SM90 FP8 path, `F16QToF8Converter` converts that Q directly to E4M3 at unit scale. The wrapper's `q_scale=(softmax_scale*K_scale/V_scale)*sqrt(D)` compensates the accumulator scale; it does not divide Q before conversion. At D256 and K=.125, changing V=.0625 to .5 changes that wrapper scalar from 2 to .25 while leaving the intended QK factor `1/128` and Q's FP8 zero threshold `2^-10` unchanged. Thus V=.5 introduces no extra Q underflow through this scalar. Independent BF16-cohort Query error remains hypothetical; it is not an observation of XQA's actual quantized-model activations. See [the source scale trace](FP8_XQA_SCALE_TRACE_20261106.md).

The mixed FA3/XQA split is **absent** from this final source. Its corrected predecessor matched direct FlashInfer, but latency ratios on the three frozen cases were `1.222349 / .386625 / .787723`; geometric mean `.719371` did not rescue the first case's failure of the `<=1.15` limit. That gate remains failed, and the earlier correctness failure is preserved. Normal mixed work uses the full FA3 batch; only pure decode uses XQA. Shared Scheduler, Graph runner and GDN code are unchanged.

The retained one-pass query kernel reads input strides directly. Six original fixtures passed bitwise checks and the `<=1.05` latency-ratio gate; those source-identical component results were reused. Large strided cases improved, while contiguous cases were approximately neutral. The model's Q normalization/partial rotary path ends with `torch.cat` then reshape, producing contiguous Query in the inspected source. The strided microbenchmark therefore does not establish model service acceleration.

Scope is SM90 dense full attention with logical D128/256 and GQA groups >=4. Actual H800/model evidence is **BF16 Q24/KV4/D256/page128**; broader admission is not model qualification. MLA/indexer, padded dimensions, PD transfer and host offload are excluded. Official CUDA rejects VMM before model loading; the historical BF16 VMM attempt failed there. XQA explicitly rejects VMM and sliding windows. Host geometry tests do not qualify mapping/reclaim, elastic capacity or unmapped pages; the default resident allocator is used.

The retained operator passed at both V=.0625 and .5: independent writer-byte checks, full-cache byte agreement with the independent compressed snapshot including invalid slots, finite outputs, and direct FA3/XQA conformance with max absolute error zero at the unchanged `.001/.001` tolerance. This is library conformance, not equality to BF16 dense attention; the historical FA3 dense `.02` tolerance failure remains recorded. Source-matched model qualification passed 16 known requests, real prefix reuse/GDN restoration, and six successful Graph API launches in a fresh three-request window. It does not establish all-request or formal mixed-batch Graph coverage.

The formal quality comparison retains all 1,720 core generations, original EOS/caps and denominators, plus 32 native multi-turn tool tasks. Scores below are rounded percentages; tools are correct tasks.

| Arm | GSM8K flexible EM | LongBench eight-task macro | RepoBench-P | Tools |
|---|---:|---:|---:|---:|
| BF16 A | 96.7399545110 | 53.8984440135 | 43.92 | 26/32 |

The final recipe satisfies the frozen point-loss limits against both A and original FP8: GSM8K .5 percentage points, LongBench macro 1 point, RepoBench-P 2 points and one tool task. **RepoBench-P versus A is -1.08 points with paired 95% interval `[-6.0605, 2.801]`, so noninferiority at the two-point margin remains inconclusive.** Original FP8's 4.18-point RepoBench-P loss to A also remains a failure under this gate. These engineering thresholds are not user-approved SLOs. RepoBench-P is completion similarity, not execution success; the tools subset is not the full BFCL leaderboard. The single long supplement scored 50% for every arm and is excluded from the macro.
