# Native KV cache on SM90

This branch adds OCP MXFP4 resident KV storage. **The implementation is qualified within the narrow scope below; its measured model quality fails the frozen engineering gate and remains research-only.**

Measured Python source is [`e10830c907bbae57e8e5dbb9e316303996059ef0`](https://github.com/MingASA/xllm_quant_kvcache/commit/e10830c907bbae57e8e5dbb9e316303996059ef0). It repairs the pinned FlashInfer non-split Graph task mask and retains full planning. The unchanged compiled xLLM source is `ba5eaec0a1b5b941da4b8ded0343d43f2c2b4158`, derived from native C `da7c6446ff4361c8060633b04d6bfb77e6f737ff` and official xLLM `261274e5f45449e98d7740144c3a958a29f1fd3e`. BF16 A remains `721afdabc1de1af8e594b4da3e6fa926def50821`; dependencies were not upgraded. Exact native source/generator/adapter hashes qualify reuse of the compiled JIT library. The CUDA/NPU build guard, byte-page geometry and lazy BF16 kernel import remain separate changes; no old research branch was merged. This documentation-only delivery does not replace measured identities; binary and JIT hashes remain in the run manifests.

| Format | Resident bytes per K or V head, D=256 | Prefill | Pure decode |
|---|---:|---|---|
| BF16 (`auto`) | 512 | Official FlashInfer selection | Official FlashInfer selection |
| `fp8_e4m3` | 256 | FA3 with FP8 query | XQA with BF16 API query |
| `nvfp4` | 144 | FlashInfer native FA2 | FlashInfer FA2 tensor-core wrapper |
| `mxfp4` | 136 | Pinned private FlashInfer FA2 adaptation | Same paged FA2 adaptation, one query/request |

The inherited FP8/NVFP4 paths have separate historical evidence; MXFP4 qualification does not extend it. Backend incompatibility fails explicitly. There is no failure-driven fallback.

Use the CUDA Python Executor with `--kv_cache_dtype=mxfp4`, `--kv_cache_prefill_backend=auto|fa2`, `--kv_cache_decode_backend=auto|flashinfer`, and `--kv_cache_k_scale=1 --kv_cache_v_scale=1`. MXFP4 admission requires **SM90, BF16 input/output, Q24/KV4/D256, page128, paged NHD full attention, no sliding window and no VMM**. Other global scales are rejected. D128/FP16 admission in the shared native backend does not apply to MXFP4. Ragged attention, MLA/indexer, padded dimensions, PD transfer and host offload are outside this qualification.

MXFP4 uses E2M1 elements with one E8M0 scale per 32 consecutive channels, as specified by [OCP MX v1.0](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf). This differs from NVFP4's E4M3 block-16 scales. E2M1 magnitudes are `0, .5, 1, 1.5, 2, 3, 4, 6`; the earlier channel occupies the low nibble. For finite nonzero blocks, the writer selects `e=clamp(floor(log2(absmax))-2,-127,127)`, stores E8M0 code `e+127`, and rounds elements to nearest, ties to even, with saturation. Signed zero is retained; an all-zero block uses code 0, meaning scale `2^-127`. A block containing a nonfinite input receives scale code 255 and zero payload, yielding a NaN block on reconstruction. Infinity preservation is not supported.

Native formats own contiguous byte tensors with typed/strided aliases. Each MX page stores the whole packed-data plane followed by the E8M0 scale plane; whole-page prefix copies include both. At D256 this is `128+8=136` bytes/head, or 4.25 bits/value. For Q24/KV4, K+V cost 1,088 bytes/token/FullAttention layer. The model qualification allocated 5,069 pages across 16 FullAttention layers: **11,294,867,456 resident bytes and 648,832 pooled physical token slots (648,704 usable after reserving page 0)**. The `64/17` capacity ratio versus BF16 applies only to an equal FullAttention KV budget, not whole-model capacity or a per-request context limit. GDN convolution/recurrent dtypes, state interface and separate budget are unchanged.

The adapter pins FlashInfer 0.6.18.post1's attention header (`f93cbea96e3a…`; adapted `b06c014c4f93…`) and rejects an incompatible header. H800 has no Blackwell FP4 Tensor Core compute. E8M0 bytes expand only within the current tile; scales are decoded in FP32, converted to BF16, and multiplied with BF16 E2M1 fragments for BF16 MMA with FP32 accumulation. There is **no FP16 scale conversion, global expanded-scale plane or full-cache BF16 shadow**. All finite E8M0 scales, including values below `2^-24` and above `2^15`, are representable in BF16. Full-attention overflow/nonfinite behavior remains bounded by the BF16/FP32 compute path; writer edge tests do not qualify arbitrary extreme attention inputs.

This adaptation retains full FA2 planning and scratch memory, caching only constant query indptr. Compared with native NVFP4, it uses two writer launches, synchronous tile scale loading/duplication, and Graph metadata staging; pure decode retains the prefill wrapper's uint8-KV split-KV safety restriction. Their separate service-time contributions are unmeasured. The direct-replan candidate reduced host API time about 75%, but increased B32/KV16384 Graph GPU time 9.15139517972632%, exceeding the frozen 5% limit. It is not the production route. Compression alone establishes no throughput advantage.

Official CUDA at the frozen base rejects `enable_vmm_kvcache` before model loading. The historical BF16 VMM attempt failed at that guard; MXFP4 rejects VMM explicitly. Host page-geometry tests do not qualify mapping/reclaim, elastic capacity or unmapped pages. The default resident allocator is used.

Writer bytes and edge cases match the independent CPU reference. The repaired-path operator pilot's 25 comparisons and main's 17 comparisons had maximum absolute errors `0.007230281829833984` and `0.0027425289154052734`, within unchanged `atol=rtol=.02`. The oracle independently decodes quantized KV before dense attention; it does not measure quantization loss relative to unquantized KV. The 8192-token prefill executes all queries and checks 16 fixed reference rows; decode checks all rows. Dirty workspace, active/padded tasks, changed lengths/page IDs and whole-page data/scale copies are covered. Changed-input Graph replay matches direct execution. The repaired model passed 16 known requests, 8192 real cross-request prefix-reuse tokens with GDN restoration, and a three-request observation window with six successful Graph API calls. This is not all-request or formal mixed-batch Graph coverage. Shared Scheduler/Graph/GDN code was not rewritten.

The formal quality comparison retains all 1,720 core generations, original EOS/caps and denominators, plus 32 native multi-turn tool tasks. Scores below are rounded percentages; tools are correct tasks.

Against A/original FP8, repaired MXFP4 loses **0.909780/0.758150 percentage points on GSM8K and 7.44/3.26 on RepoBench-P**, exceeding the frozen limits of .5 and 2 points. LongBench macro losses .652504/.018275 are within its one-point engineering limit; versus A its paired 95% interval is `[-2.231815, .906024]`, so statistical noninferiority is not established. RepoBench-P's interval is `[-14.821, -.72]`. All 1720 records remain: 82 capped generations and 8 empty natural-EOS answers (scored zero) were neither extended nor resampled. The long supplement scored 50% and is excluded from the eight-task macro. RepoBench-P measures completion similarity, not code execution success; the tools subset is not the full BFCL leaderboard.

Tools score **23/32**, three tasks below A/original FP8 and four below NVFP4; the frozen limit permits losing at most one task. All 32 tasks remain, including one incomplete task, with 109/112 user turns completed. Inputs, concurrency4, ten steps/turn, 1024 new tokens/call and the 3600-second budget are unchanged. The original tools card was occupied by another user, so this semantic-quality run explicitly used the already qualified GPU0 instead of historical GPU1. It is not a same-physical-card tool performance comparison; core quality and all three service comparisons retain their original GPU0.

The repaired-path independent raw-service audit completed all 512/512/64 original requests with natural EOS and unchanged caps on the same H800 GPU as A. Output tokens/s were **607.2856506218478, 671.7286304159918, 114.7634296662263** for ShareGPT C32/C64 and GovReport C32: **13.23%, 15.37%, 27.98% below A**. GovReport's maximum running requests increased from 13 to 32, but P95 request-mean ITL rose to 3.98 times A. Two loose GovReport Goodput thresholds improve; the full 16-point sensitivity matrix is retained and is not a business SLO. Real cross-request prefix hits were zero in all three formal workloads.

**Merge recommendation:** review codec, resident layout, writer/copy and explicit capability checks as experimental support; review the task-mask correctness fix independently. Do not promote this MXFP4 attention path to a production default, or merge the rejected replan candidate based on host-only speedups. FP8's separately validated retained scale recipe remains an opt-in path; this work makes no new FP8 performance claim.
